# Agent Note: 静态工作流所有者测试无需打包即可选测

Status: implemented

[English](2026-09-14-static-workflow-ci-ownership.md) | 中文

## Problem

应用目录中的测试可能只检查 GitHub 工作流。如果把这类测试一律视为应用变更，即使没有任何打包输入变化，也会选择完整 Desktop 测试集、产品组装和两个平台任务。

## Decision

fork CI 规划器维护一张经过审阅的显式表，将工作流映射到检查仓库文本的测试。规划器会先识别完整的工作流与所有者组合，再判断包归属；这些测试在 quality 任务中运行，发生变化的所有者也在该任务中接受 lint，build、product 和 Desktop 任务保持未选择。作为每个已登记测试的防护，规划器拒绝 TypeScript 可发现的相对路径、私有 alias 和工作区包 import；动态读取与子进程行为仍由审阅负责。源文件、manifest、资源、共享 fixture、lockfile、submodule，以及表外测试继续沿用现有包归属与消费方选择规则。

工作流与全部列出的所有者必须同时存在。组合不完整时，规划会失败。完整组合被删除时，会回落到现有的变更前后归属逻辑，因此检查范围会扩大，而不会从计划中消失。重命名会保留旧路径删除时的保守检查，并拒绝新工作流路径，直到它获得显式所有者映射。规划器、runner、已登记仓库策略或固定回归测试发生变化时，会选择完整 fork CI 回归集。任务摘要为每个运行或跳过的任务记录一条有界原因；artifact 保留完整计划。

## Alternatives considered

**所有仅修改测试的应用变更都只跑 quality。** 不采用，因为应用测试可以导入运行时代码或共享 fixture，因此可能负责产品行为。

**所有应用测试都运行完整 Desktop 与 product 检查。** 不采用，因为经过显式审阅的工作流文本所有者不会改变打包输入，而真实发布行为仍由已签名发布工作流验证。

**从任意测试 import 推断归属。** 不采用，因为动态读取和子进程使通用 import 图无法证明归属。经过审阅的表保持显式；import 扫描只作为防止明显包代码依赖的额外防护。

## Consequences

Desktop Release 工作流及其映射的静态测试发生变化时，会通过 quality 运行而无需重新构建产品。固定汇总检查仍会拒绝缺失、失败、取消或计划外运行的任务。新增所有者需要经过审阅的表项，并增加聚焦的正例、删除、重命名、未知路径、共享 fixture 和规划器自身回归用例。
